# AI-slop 反面清单(写否定清单/跑 slop 检测用)

## 证据链(为什么模型配色差)

1. **中位数陷阱**:LLM 是统计模式匹配器,模糊指令下输出训练数据的中位数。"你得到的是 2019-2024 年 GitHub 上所有 Tailwind 教程的中位数,而那个中位数是紫色的"——Tailwind 组件库当年随手选了 `bg-indigo-500` 做演示色,教程互相抄袭,训练数据把它吸收成"现代网页=紫色按钮"。(prg.sh: Why Your AI Keeps Building the Same Purple Gradient Website)
2. **模型看不见颜色**:ColorBench(arXiv:2504.10514,NeurIPS 2025 D&B)系统评测 VLM 的色彩感知/推理/鲁棒性,结论:模型更大略好,但整体色觉理解仍然有限。模型是在"操作颜色的文字",不是"看着颜色设计"。
3. **忽视可读性约束**:设计社区反复实测,AI 工具给出的 hex 组合经常过不了自家配色的 WCAG 对比度(r/webdesign 等,社区层证据)。
4. **修法有效**:显式指定维度、参照具体美学、推理期否定禁用项、一次出多方案——"模型能执行,方向必须由你供给"。(prg.sh 修复清单,与 frontend-design skill 的反模板纪律同源)

## 颜色黑名单(slop 检测已内置)

| 签名 | 具体 hex | 为什么 |
|---|---|---|
| Tailwind 默认族 | #3B82F6 #6366F1 #8B5CF6 #A855F7 #EC4899 #4F46E5 #0EA5E9 #22D3EE | 训练数据中位数本体,出现即"一眼 AI" |
| 紫渐变对 | 两个 H∈[250°,310°]、C>0.12、ΔL<0.2 的紫 | #1 AI-slop 签名 |
| 平坦明度 | 全板 L 极差 <0.25 | 没有明度架构=文字/背景必然失败 |
| 全高饱和 | 全板 C>0.16 且 L>0.45 | 没有安静的面,内容无处安放 |

## 版式黑名单(frontend-design 已列,配色相关项)

1. 暖奶油底(≈#F4F1EA)+ 高对比衬线大标题 + 陶土色点缀——当前 AI 三大默认长相之一;
2. 近黑底 + 单一荧光绿/朱红点缀——同上;
3. "大数字+渐变点缀+深色背景"是最泛滥的 hero 模板。

注:这三条是**默认即嫌疑**——brief 明确要求时照做,brief 没约束时别把自由花在默认上。

## 否定清单模板(直接抄进设计 prompt)

```
禁用:Tailwind 默认蓝/靛/紫家族(#3B82F6/#6366F1/#8B5CF6 及其渐变组合)
禁用:紫→粉/紫→蓝渐变背景
禁用:Inter/Roboto 配这套颜色(换有性格的字体)
禁用:所有颜色同明度
要求:参照美学「<一句话,如:中药铺抽屉:深褐、米黄、朱砂印泥红」
要求:正文对比度≥4.5:1,图表色块≥3:1,红绿不同时作唯一区分
```

推理期否定是模型可执行的操作(实证有效),写出来就比不写强。
